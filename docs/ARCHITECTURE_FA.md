# معماری میزکار اطلاعات راهبردی — سند فاز ۰

**نسخه:** ۰٫۱ (پیش‌نویس) · **تاریخ:** اکتبر ۲۰۲۶
**تصمیم‌های قفل‌شده:** تکامل `app/` فعلی · ادغام موتور `persiaa-doctrine` · آفلاین-first (LLM بعداً و opt-in)

## ۱. مرز محصول

| داخل MVP | بیرون MVP (جدا نگه داشته می‌شود) |
|---|---|
| داشبورد دکترین (`app/doctrine.html`) + پروکسی چت (`app/server.py`) | ربات‌های ایتا/بله (Selenium)، دانلودر تلگرام |
| موتور قاعده‌محور از `persiaa-doctrine` (MIT) | OSINT شبکه‌ای (فقط افزونه مجاز، فاز ۵) |

| OCR فارسی آفلاین (text-layer اول، Tesseract fallback) | اتصال LLM (فاز ۶، opt-in با رضایت صریح) |

## ۲. وضعیت صادقانه فعلی (چه چیزی واقعی است و چه چیزی قالبی)

- ✅ پروکسی چت OpenRouter/HF با `/health` و `/api/chat` واقعی و تست‌شده.
- ✅ داشبورد با داده seed واقعی (۱۵ سند، گراف گفتمانی، OCR) و خودآزمایی موتور ۵۱/۵۱.
- ⚠️ «کامپایلر مأموریت»، «استودیو محتوا» و «گردش‌کار ارکستراسیون» **قالب‌محور**‌اند: تشخیص نیاز با چند واژه، شبیه‌سازی با مقادیر ثابت، Shadow Audit چک‌لیست متنی. این‌ها تحلیل LLM یا عامل واقعی **نیستند** و در UI باید با برچسب «پیش‌نویس قاعده‌محور» مشخص شوند (فاز ۱).
- ⚠️ ادعاهای seed عموماً فقط نام سند دارند؛ نقل‌قول/صفحه/URL نظام‌مند ثبت نشده (فاز ۱: provenance واقعی).

## ۴. سیاست آفلاین-first

- حالت پایه بدون هیچ اتصال شبکه کار می‌کند؛ داشبورد از داده ازپیش‌ساخته‌شده کاملاً آفلاین باز می‌شود.
- هر قابلیت شبکه‌ای (LLM، OSINT، دانلود) فقط opt-in، با نشانگر «اتصال بیرونی»، ثبت مقصد داده و رضایت کاربر.
- داده حساس پیش‌فرض فقط روی دستگاه؛ SQLite محلی؛ بدون ارسال خودکار به سرویس بیرونی.
- خروجی قالبی هرگز به‌عنوان خروجی LLM معرفی نمی‌شود.
